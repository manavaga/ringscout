# RingScout Security Policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in public GitHub issues, pull requests or discussions.

Use GitHub's private vulnerability reporting feature for this repository if it is enabled. If private reporting is not available, contact the operator at **agarwalmanav91@gmail.com** and request a secure reporting channel.

## What to include

Please provide:
- a clear description of the issue and its potential impact;
- affected endpoint, component or version;
- reproducible steps or a proof of concept that does not access or expose other people's data;
- any suggested mitigation.

Do not include real customer data, private call audio, secrets, API keys or payment credentials in a report.

## Scope and responsible testing

Do not disrupt the service, conduct denial-of-service testing, access data belonging to other users, place nuisance calls, or test against third-party businesses without authorization. Please allow the operator a reasonable opportunity to investigate and remediate before public disclosure.

## Response expectations

RingScout is an independently operated project and does not currently promise a formal security response SLA or bug bounty. Acknowledgment and remediation timing may vary.
